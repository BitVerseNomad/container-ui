# Iteration 11: Packaging, Release, and Hardening (W11+W12)

Date: 2026-11-03. Status: awaiting review.

## Intent

Ship Colima UI as a polished macOS application: code-signed, notarized .dmg with universal binary (Apple Silicon + Intel), distributed via GitHub Releases with an updater plugin, and optionally installable via Homebrew. Harden the app with CSP enforcement and typed commands over time.

**Success:** Users can download, install, and update Colima UI seamlessly; the app passes Apple's notarization; security review confirms CSP and command allowlists are effective.

## Scope

**In:**
- **Icons and assets:** App icons for all required sizes (16px, 32px, 128px, 256px, 512px), tray icon, splash/launch image
- **`npm run tauri build`:** Production build producing a .dmg installer
- **Universal binary:** Build for both `x86_64` and `aarch64` (Apple Silicon + Intel)
- **Code signing:** Sign the app with an Apple Developer certificate
- **Notarization:** Submit to Apple for notarization (requires Apple Developer account)
- **GitHub Releases:** Automate .dmg uploads via `tauri-action` in CI
- **Homebrew tap/cask:** Optional Homebrew installable cask (depends on whether distribution is needed)
- **Updater plugin:** Tauri updater plugin for automatic updates from GitHub Releases
- **CSP enforcement:** Confirm the release build loads under the existing CSP on a real Mac
- **Command allowlists:** Docker calls go through per-command flag allowlists (already implemented; verify in release build)
- **Typed commands over time:** Migrate from string-based commands to typed command definitions
- **Research first:** Tauri build configuration, code signing process, notarization workflow, updater plugin setup, Homebrew cask creation

**Out:**
- Windows or Linux builds (this iteration is macOS-only)
- Electron or web-based distribution (Tauri/macOS only)
- Custom software update server (GitHub Releases + updater plugin is sufficient)
- Multi-language installers (English .dmg only for now)

### 3. Universal Binary Build

```bash
# Build universal binary (x86_64 + aarch64)
export CARGO_TARGET_X86_64_APPLE_DARWIN_LINKER=clang
export CARGO_TARGET_AARCH64_APPLE_DARWIN_LINKER=clang

npm run tauri build -- --bundles dmg --target universal-apple-darwin
```

The `--target universal-apple-darwin` flag tells Tauri to build both architectures and create a universal binary.

### 4. Code Signing and Notarization

```bash
# Code sign the app
codesign --sign "Developer ID Application: Your Name (TEAM_ID)" \
  --options runtime \
  --entitlements src-tauri/entitlements.plist \
  dist/mac/Colima UI.app

# Code sign the .dmg
codesign --sign "Developer ID Application: Your Name (TEAM_ID)" \
  dist/mac/Colima UI.dmg

# Submit for notarization
xcrun notarytool submit dist/mac/Colima UI.dmg \
  --team-id "TEAM_ID" \
  --apple-id "your@appleid.com" \
  --password "@keychain:NOTARY_PASSWORD" \
  --staple

# Staple the notarization ticket to the app
xcrun stapler staple dist/mac/Colima UI.app
```

**Entitlements (`src-tauri/entitlements.plist`):**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>com.apple.security.cs.allow-jit</key>
  <true/>
  <key>com.apple.security.cs.allow-unsigned-executable-memory</key>
  <true/>
  <key>com.apple.security.cs.disable-library-validation</key>
  <true/>
  <key>com.apple.security.device.audio-input</key>
  <true/>
  <key>com.apple.security.device.camera</key>
  <true/>
</dict>
</plist>
```

### 5. GitHub Actions: Automated Releases

```yaml
# .github/workflows/release.yml

name: Release

on:
  push:
    tags:
      - "v*"

jobs:
  release:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Build Tauri app
        uses: tauri-apps/tauri-action@v0
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          APPLE_ID: ${{ secrets.APPLE_ID }}
          APPLE_PASSWORD: ${{ secrets.APPLE_PASSWORD }}
          APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}
          CODE_SIGNING_CERTIFICATE: ${{ secrets.CODE_SIGNING_CERTIFICATE }}
          CODE_SIGNING_CERTIFICATE_PASSWORD: ${{ secrets.CODE_SIGNING_CERTIFICATE_PASSWORD }}

      - name: Create Homebrew PR (optional)
        run: |
          # Update Homebrew cask if distribution requires it
          brew bump-formula-pr --url "$(curl -sI https://github.com/<user>/<repo>/releases/latest | grep -i location | awk '{print $2}')"
```

### 6. Updater Plugin Setup

```rust
// src-tauri/src/updater.rs

use tauri_plugin_updater::UpdaterExt;

fn setup_updater(app: &mut tauri::App) {
    let updater = app.updater().clone();
    
    tauri::Builder::default()
        .plugin(tauri_plugin_updater::builder().build())
        .setup(move |app| {
            // Check for updates on startup
            tokio::spawn(async move {
                let update = updater.check().await;
                match update {
                    Ok(Some(update)) => {
                        println!("Update available: {}", update.version);
                        // Show a notification to the user
                        // (integrating with the notification system from Iteration 09)
                    }
                    Ok(None) => {
                        println!("App is up to date");
                    }
                    Err(e) => {
                        eprintln!("Error checking for updates: {}", e);
                    }
                }
            });
            
            Ok(())
        })
        .run(app)
}
```

The updater plugin requires:
1. A `update.json` file in the GitHub Releases assets
2. The updater public key (generated via `tauri updater sign`)
3. The `.dmg` and `update.json` in the same release

### 9. Typed Commands Over Time (W12)

Migrate from string-based Docker commands to typed command definitions:

```rust
// src-tauri/src/commands/docker/typed.rs

// Current: string-based commands with flag allowlists
#[tauri::command]
async fn docker_ps(filter: Option<String>) -> Result<Vec<ContainerInfo>> {
    let cmd = if let Some(f) = filter {
        format!("docker ps --filter '{}'", sanitize(&f))
    } else {
        "docker ps".to_string()
    };
    execute_docker_command(&cmd).await
}

// Future: typed command definitions
#[derive(Debug, Clone, Serialize)]
struct DockerPsCommand {
    filter: Option<ContainerFilter>,
    all: bool,
    format: Option<String>,
}

#[derive(Debug, Clone, Serialize)]
struct ContainerFilter {
    key: String,
    value: String,
}

#[tauri::command]
async fn docker_ps_typed(cmd: DockerPsCommand) -> Result<Vec<ContainerInfo>> {
    // Build the command from typed fields, not from user strings
    let args = build_docker_ps_args(&cmd);
    execute_docker_command_with_args("docker", &args).await
}

fn build_docker_ps_args(cmd: &DockerPsCommand) -> Vec<&str> {
    let mut args = vec!["ps"];
    if cmd.all {
        args.push("-a");
    }
    if let Some(filter) = &cmd.filter {
        args.push("--filter");
        args.push(&format!("{}={}", filter.key, filter.value));
    }
    if let Some(format) = &cmd.format {
        args.push("--format");
        args.push(format);
    }
    args
}
```

Benefits of typed commands:
- No string拼接 errors (command structure is enforced by the type system)
- Easier to audit and review (each field is explicit)
- Easier to add new flags (just add to the struct)
- Better documentation (the type is self-documenting)

### 11. Risks & Mitigations

| Risk | Severity | Mitigation |
|------|----------|------------|
| Apple Developer account is required for code signing and notarization | High | Acquire before starting this iteration; cost: $99/year |
| Notarization may reject the app for missing entitlements | High | Test entitlements thoroughly; use `codesign --verify --deep --strict` before submission |
| Universal binary builds may take longer (two architectures) | Low | Accept the longer build times; use CI caching to speed up subsequent builds |
| Homebrew cask maintenance adds ongoing overhead | Medium | Only include if distribution is a requirement; otherwise skip |
| CSP may block legitimate resources in the release build | Medium | Test on a real Mac; adjust CSP directives if needed (but prefer fixing the root cause) |
| Updater plugin may fail if the GitHub release structure is incorrect | Medium | Follow Tauri's updater documentation exactly; test the update flow manually |
| Code signing certificate may expire between releases | Medium | Store the certificate in GitHub Secrets; rotate before expiration |

### 12. Open Questions

- Should the updater check for updates manually (user-initiated) or automatically on startup? (Proposal: check on startup, but only notify the user — require a click to install)
- Should the .dmg include a README.txt or license file? (Proposal: yes, include a simple text file with licensing info and a link to the full license)
- Should the Homebrew cask be in a public tap or a private one? (Proposal: public tap if distribution is intended; otherwise skip Homebrew)
- Should the updater support delta updates (only ship the diff between versions)? (Proposal: no, full .dmg updates are simpler and the .dmg is small enough)
- Should there be a "Check for Updates" option in the settings? (Proposal: yes, in addition to automatic checks)
- How many Docker commands need typed definitions? (Proposal: start with the most common ones — ps, images, logs, start, stop, restart, rm, rmi, network, volume — and add more as needed)
